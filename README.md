# xxxr

the best porn site.

Flutter Web frontend with a Node.js / Next.js API and Neon PostgreSQL database, hosted on Render. An 18+ confirmation screen appears before the library and remembers confirmation for the current browser tab session. This is self-declared age confirmation, not identity or age verification.

Admin entry: `/admin-login`. The protected `/admin` dashboard supports publishing and deleting videos, searching the collection, and granting or revoking premium membership. Sign in with the administrator email and password. API operations also enforce administrator authorization. Passwords use salted scrypt hashes. Database-backed sessions use random tokens in HttpOnly, Secure production cookies; only token hashes are stored. Identity headers from the former Sites host are never trusted. Login attempts are rate limited in PostgreSQL.

The administrator dashboard includes **Videos**, **Categories**, **Performers**, **Tags**, and **Members** tabs. Create, rename, and remove category/tag names, and manage performer names, biographies, and HTTPS profile images. Videos support multiple categories, performers, and tags. Edit an existing video's title, description, embed link, preview image, assignments, and premium status. Removing a catalog entry removes only its assignments; the videos remain. Duplicate names within each group are rejected without regard to case or repeated spaces.

The public library filters by category, performer, and tag, and searches titles, descriptions, and assigned names. Shared-name edits appear throughout the library on refresh. The catalog migration preserves existing videos and imports their previous category labels. `/api/catalog` and the catalog lists are public; all catalog writes and video edits require an administrator session and an allowed origin. `tests/catalog-e2e.mjs` verifies catalog CRUD, filtering, edit propagation, permissions, transactional validation, and safe removal.

Admin: `rajuit1396@gmail.com` by default, configurable with `ADMIN_EMAIL`. Members sign in or create accounts at `/login`. Email verification and password recovery are not configured. Publish HTTPS embed links or paste iframe code, remove videos, and grant or revoke premium access. Only the iframe src URL is retained; supplied HTML is never rendered. YouTube and Vimeo share links are normalized automatically. Other providers require their player/embed URL and must permit iframe playback. Players run in a sandbox without top navigation or popups.

New videos appear immediately after publishing; other open browsers refresh every 30 seconds. Premium embed URLs are returned only after server authorization. No payment processor is configured: premium access is granted manually. Public provider URLs can still be accessed outside this website. Protected media requires provider-side access controls.

Video cards show preview images in the library and administrator dashboard. YouTube thumbnails are detected directly; Vimeo uses oEmbed; other public HTTPS players are checked for Open Graph, Twitter image, video poster, or structured thumbnail metadata. Metadata requests pin DNS to public IPv4 addresses, recheck redirects, and limit response size and duration. Unavailable images fall back to a branded preview. Administrators can supply a custom HTTPS preview URL when publishing, or choose **Edit preview image** on an existing video. A blank value retries automatic detection. Preview images are public, including for premium videos; player URLs remain behind playback authorization.

To detect thumbnails for existing records, run `node --env-file=.env.local scripts/backfill-previews.mjs`. This fills only empty thumbnail fields and preserves custom images. Preview checks: `node --test tests/video-preview.test.mjs`.

Render configuration is in `render.yaml`. Set `DATABASE_URL` to Neon's pooled PostgreSQL connection string, `DATABASE_URL_UNPOOLED` to its direct connection string for migrations, `APP_URL` to the public origin, and `ADMIN_INITIAL_PASSWORD` to a strong password of at least 12 characters. Keep credentials in Render environment variables, never in Git. Build with `npm ci --include=dev && npm run build`; start with `npm run db:migrate && npm start`. Next.js binds to `0.0.0.0` and uses Render's `PORT`. `/healthz` checks database connectivity.

The production origin is `https://www.xxxr.online`. `APP_ALLOWED_ORIGINS` is a comma-separated list of additional allowed origins: `https://xxxr.online,https://xxxr.onrender.com`. Login and administrator writes validate the request Origin against this explicit list. Origins are normalized before comparison; unrelated hosts, missing/null origins, HTTP variants, and unexpected ports remain rejected.

`npm run db:migrate` applies versioned Drizzle PostgreSQL migrations from `drizzle/postgres` through the direct connection and seeds the administrator once. Subsequent runs preserve the stored password and data. Changing `ADMIN_INITIAL_PASSWORD` does not reset an existing administrator password. The older SQLite migration files are retained as history and are not applied to Neon. Existing Cloudflare D1 data is not copied automatically.

Neon services are declared in `neon.ts`; `.neon` preserves the selected project and branch locally and is ignored by Git. Run `neon deploy` to apply the service policy and pull `DATABASE_URL`, `DATABASE_URL_UNPOOLED`, and `NEON_BRANCH` into `.env.local` (or an existing `.env`). Postgres is the only declared service; the app retains its own login and sessions.

For local development, configure the app variables in the ignored `.env.local` and use `npm run dev`. `npm run db:migrate` loads `.env` and `.env.local`, with existing process environment variables taking precedence. Check passwords and safe redirects with `npm run test:auth`. After building, start on port 3100 (`npm start -- --port 3100`) with `APP_URL=http://127.0.0.1:3100`, then run `npm run test:e2e`. The test verifies live Neon persistence, registration, administrator login, premium permissions, and session invalidation, and removes only its own temporary data. For another origin, set `TEST_BASE_URL` and the matching server `APP_URL`.

The compiled Flutter frontend is committed in `public/watch`. To update it, run `flutter build web --base-href /watch/` from `flutter_app` and copy `flutter_app/build/web` into `public/watch`. The old sign-in URL remains as a redirect to `/login` for compatibility with the compiled frontend. Legacy Sites tooling is retained in the repository but is not used by the Render build or runtime.

Public-library advertising loads after age confirmation: the supplied popunder and social-bar scripts load once per page, and the native banner appears in a labeled, sandboxed iframe. The sponsored smartlink opens in a new tab only when clicked. Ad providers control inventory and display; ad blockers can suppress placements. The dedicated Next.js login and admin pages do not load these scripts. Native banner markup is maintained in flutter_app/web/native-ad.html and copied to public/watch by the Flutter build.
